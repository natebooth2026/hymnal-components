# DATA_NOTES — what's in this folder and how it was made

All data here is **synthetic and deterministic** — generated by a seeded script (seed 42), so this exact dataset can be regenerated byte-for-byte. No real people. Every full name is unique (so name-based joins are unambiguous), all emails use `@example.com`, all phone numbers use the reserved `555` block.

## Files

| File | Data rows | What's in it |
|---|---|---|
| members.csv | 250 | ~15% blank emails, ~8% blank phones; statuses ~72% active / 18% inactive / 10% visitor; join dates spread over 8 years |
| giving.csv | 5,319 | Jan 2025 – Jun 2026. Sunday-clustered dates; regular givers repeat a "usual amount"; realistic curve (mostly $10–$100, a few $500–$2,000); ~3% anonymous gifts; funds and methods weighted like a real church |
| attendance.csv | 5,665 | Oct 2025 – Jun 2026 on actual service days; active members attend Sunday Morning most, some Sunday Evening / Wednesday Night; visitors appear only in recent weeks |
| events.json | 24 | Field names match Hymnal's real `Event` interface (`start_date`, `max_attendees`, `status`, …). Scenarios included: nearly full, full with waitlist, full without waitlist, deliberately over-subscribed, unlimited-as-`null`, unlimited-as-`0`, lightly booked, zero-ish registrations, and past `completed` events |
| registrations.json | 147 | Party sizes 1–6; all five statuses represented (`registered`, `confirmed`, `attended`, `waitlisted`, `cancelled`); mix of member and guest registrants |
| messy-import.csv | 300 | 20 seeded invalid cells + 1 exact-duplicate pair + 1 quoted-comma trap row that must NOT be flagged. Full answer key: `MESSY_CSV_MANIFEST.md` |

(Each CSV also has 1 header line above its data rows.)

## Quirks that are ON PURPOSE

- **The CSVs end without a trailing newline.** That matches a real constraint of Hymnal's importer — the Task 0 spec tells the story.
- **Blank emails and phones appear throughout.** Components must render them gracefully (a dash or empty cell), never print the string "null", and never crash.
- **Event e14 is over-subscribed** (13 seats taken against a cap of 10). Bad data like this exists in the wild; a robust component caps its bar at 100% and shows "Full" instead of breaking.
- **A name with an apostrophe (O'Brien) is in the member pool, and messy-import.csv row 90 contains the quoted-comma name `Robert Smith, Jr.`** — both exist specifically to catch naive string handling.

## Same data, two formats

The identical records also exist as typed TypeScript in `starter/src/data/` (`big-data.ts` for members/giving/attendance, `events.ts` for events/registrations) so components can import them directly with no CSV parsing. The raw CSVs in THIS folder are for the importer-related tasks (Task 0 as reference output, Task 2 as validation input).
